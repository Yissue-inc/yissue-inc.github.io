# AI 증명사진 서비스 — 기술 원리 분석 및 구현 계획서

> 대상 레퍼런스: enhanz.io(인핸즈) 외 AI 증명사진 서비스군
> 작성일: 2026-09-13 · 문서 버전 v1.0 · 작성: Yissue Inc.

---

## 0. 3줄 요약

1. **이건 "모델 하나"가 아니라 "파이프라인"이다.** 생성 모델은 전체 체감 품질의 30% 정도만 담당한다. 나머지 70%는 ①입력 게이팅 ②아이덴티티 재주입 ③리라이팅·리터칭·업스케일 ④규격 크롭 ⑤**자동 QA 후 상위 N장만 노출**에서 나온다.
2. **"사진관 퀄리티"의 정체는 후처리다.** 스튜디오 조명(리라이팅), 피부 텍스처 보존형 리터칭(주파수 분리), 배경 그라데이션, 85mm 렌즈 원근감 — 이건 전부 생성 이후 단계에서 결정된다.
3. **진짜 해자는 모델이 아니라 "본인 같음(identity fidelity)"을 수치로 관리하는 QA 루프다.** ArcFace/AdaFace 코사인 유사도 게이트 + ICAO 규격 검증 + best-of-N 랭킹. 여기서 경쟁사와 갈린다.

### 1.1 관측 가능한 사실

| FAQ 신뢰 문구 | "샘 알트만에게 투자받은 창업자" | 기술적 해자가 아니라 **마케팅 신뢰 장치**. 기술 스택 자체는 상당 부분 공개 기술로 재현 가능 |

### 1.2 결론

인핸즈의 결과물 품질은 **독점 모델**이 아니라 **엔지니어링 완성도**에서 나온다. 공개된 기술 스택(FLUX/Qwen-Image-Edit/Nano Banana + InsightFace + IC-Light + BiRefNet + CodeFormer/DiffBIR 계열)으로 **동등 품질 재현이 가능하다.** 다만 아래 3가지를 못 하면 "얼굴이 달라져서 못 쓰는" 흔한 AI 사진이 된다.

- 아이덴티티 락(identity lock)
- 후처리 품질 규율
- 불합격 결과를 사용자에게 보이지 않는 자동 QA

## 2. 기술 원리 — 10단계 파이프라인

```
[업로드]
   │
   ├─ S0. 입력 품질 게이팅 (FIQA)          ← "필터"의 전반부: 쓸 수 없는 사진을 걷어냄
   ├─ S1. 얼굴 분석 (검출/랜드마크/포즈/파싱/속성)
   ├─ S2. 아이덴티티 표현 추출 (ArcFace·AdaFace 임베딩 / LoRA)
   │
   ├─ S3. 생성 (Route A: 편집형 | Route B: 개인화 학습형)
   ├─ S4. 아이덴티티 재주입 (face re-injection / swap)
   ├─ S5. 얼굴 복원 + 업스케일 (BFR + SR)
   ├─ S6. 리라이팅 + 배경 합성 (relight + matting)
   ├─ S7. 리터칭 "필터" 레이어 (주파수 분리 · 닷지&번 · 톤/컬러)
   ├─ S8. 규격화 (증명사진 크롭 · DPI · 배경색 · 규격 검증)
   ├─ S9. 자동 QA + 랭킹 + 워터마크/C2PA
   │
[상위 N장 노출] → 사용자 선택 → 고해상도 딜리버리
```

### S0. 입력 품질 게이팅 — "필터"의 전반부

사용자가 올리는 사진의 80%는 그대로 쓰면 결과가 망가진다. **생성 전에 거르는 것이 생성 후에 고치는 것보다 10배 싸다.**

| 체크 | 기법 | 임계값(초안) |
|---|---|---|
| 얼굴 검출 수 | SCRFD / YOLO-face | 정확히 1명 (다인 시 최대 얼굴 선택 + 경고) |
| 얼굴 픽셀 크기 | 바운딩박스 단변 | ≥ 200px (권장 ≥ 400px) |
| 선명도 | Variance of Laplacian | ≥ 100 (경고), ≥ 50 (하드 리젝트) |
| 포즈 | 6DoF head pose (yaw/pitch/roll) | \|yaw\| ≤ 30°, \|pitch\| ≤ 20° |
| 종합 유용성 | **CR-FIQA** / SER-FIQA / GraFIQs | 정규화 점수 ≥ 0.45 |
| 규격 준수도 | **OFIQ** (ISO/IEC 29794-5:2025 레퍼런스 구현) | 조명/가림/표정 서브스코어 |
| 가림 | face parsing(BiSeNet) 기반 마스크/손/머리카락 가림 비율 | 눈·코 영역 가림 0% |
| 안경 반사 | 렌즈 영역 하이라이트 클리핑 비율 | > 8% 시 경고 |

**UX 설계 포인트:** 게이팅은 *거절*이 아니라 *코칭*으로 노출한다. "이 사진은 흔들렸어요 → 다른 사진을 추가해 주세요"가 환불 요청보다 싸다. 업로드 즉시(클라이언트 온디바이스 또는 <1초 API) 피드백해야 한다.

**레퍼런스**
- OFIQ — ISO/IEC 29794-5 레퍼런스 구현, NIST SIDD에서 EDC 곡선 최상위권. ICAO 규격 검증에 사실상 표준.
- CR-FIQA (CVPR 2023) — https://github.com/fdbtrs/CR-FIQA
- SER-FIQ — https://github.com/pterhoer/FaceImageQuality
- GraFIQs — https://github.com/jankolf/GraFIQs

### S1. 얼굴 분석

InsightFace 스택(SCRFD 검출 + 2d106/3d68 랜드마크 + genderage)으로 기하 정보를 확보하고, face parsing으로 피부/머리카락/안경/의류 세그먼트를 분리한다. 이 결과는 이후 **모든 단계의 마스크 소스**로 재사용된다(리터칭 영역, 배경 합성 경계, 규격 크롭 기준점).

특히 증명사진은 **머리 크기 비율과 눈높이 위치**가 규격이므로, 정수리(hair top)와 턱끝(chin) 좌표를 정확히 잡는 것이 S8의 전제 조건이다.

### S2. 아이덴티티 표현 추출

두 갈래가 있고, **이 선택이 서비스 원가와 리드타임을 결정한다.**

| | Route A: 제로샷 어댑터 | Route B: 개인화 학습(LoRA) |
|---|---|---|
| 입력 | 1~4장 | 10~20장 |
| 준비 시간 | 0초 | 10~40분 |
| 원가 | 낮음 | 건당 $2~5 (호스팅) / 자체 GPU 시 $0.3~1 |
| 유사도 | 중~상 | 상 |
| 대표 기술 | InstantID, IP-Adapter-FaceID, PuLID, InfiniteYou | FLUX LoRA portrait trainer, DreamBooth |
| 적합 | 대중 상품(1~2만원) | 프리미엄 상품(5만원+) |

- **InstantID** — Apache 2.0, 상용 가능. IdentityNet으로 강한 의미 조건 + 약한 공간 조건. https://github.com/instantX-research/InstantID
- **InfiniteYou** (2026) — FLUX/SD3.5 계열 rectified-flow DiT 위에서 아이덴티티 보존. 현 세대 DiT에 맞는 접근.
- **PuLID / FaceCLIP** — 얼굴 유사도 벤치에서 상위. FaceCLIP-SDXL 기준 face similarity 0.869 보고.
- **알려진 함정**: InstantID·IP-Adapter+PhotoMaker 계열은 **얼굴 클로즈업으로 쏠리는 경향**이 있다. 증명사진은 상반신이므로 오히려 유리하지만, 어깨·의상 자연스러움은 별도로 관리해야 한다.

> **권장:** MVP는 Route A. 프리미엄 티어에서만 Route B. "1시간"이라는 리드타임 약속은 Route B를 쓰더라도 지킬 수 있고, Route A라면 큐 여유가 커진다.

### S3. 생성 — 두 가지 구현 경로

#### Route A-1: 편집형(in-context editing) — **MVP 권장**

원본 사진을 **참조 이미지로 직접 넣고** "이 사람을 증명사진으로 바꿔라"를 지시하는 방식. 2025~2026년 이미지 편집 모델의 급격한 발전으로 가장 실용적인 선택지가 되었다.

| 모델 | 형태 | 특징 | 라이선스/비용 |
|---|---|---|---|
| **Gemini 3 Pro Image (Nano Banana Pro)** | API | 프롬프트 준수·피사체 일관성 최상위권. 캐릭터 일관성 95%+ 주장 | $0.134/장 (1~2K), Batch API 50% 할인 → 약 $0.067 |
| **Gemini 2.5 Flash Image (Nano Banana)** | API | 속도/비용 우위 | 저가 (정확 단가 확인 필요) |
| **FLUX.1 Kontext** | API + 가중치 | 배경 통합 자연스러움, 워크플로 안정성 | 상용 라이선스 확인 필요 |
| **Qwen-Image-Edit-2509** | **오픈 가중치 Apache 2.0** | 오픈 편집 모델 1위권(Arena #3). 다중 이미지 편집(인물+인물/인물+장면), ControlNet 내장(depth/edge/keypoint) | **Apache 2.0 — 상용 자유** |
| **FLUX.2 [klein]** | 오픈 (4B/9B) | 저VRAM(13GB) 학습·서브초 추론 | 라이선스 확인 필요 |

> **전략적 결론:** **API로 시작해 Qwen-Image-Edit 계열 자체 호스팅으로 이전**한다. Apache 2.0이라 상용 리스크가 없고, 원가가 10~30배 낮아진다(§7 참조).

#### Route A-2: 프롬프트 설계

증명사진 프롬프트의 핵심은 "잘 만들어라"가 아니라 **"바꾸지 말 것"을 명시**하는 것이다.

```
[PRESERVE — 최우선]
Keep the exact facial identity: eye shape and spacing, eyelid crease,
nose bridge and tip, philtrum, lip shape, jawline, cheekbone structure,
skin tone, moles, freckles, wrinkles, and apparent age.
Do NOT slim the face. Do NOT enlarge the eyes. Do NOT remove wrinkles.
Do NOT change ethnicity. Preserve existing eyeglasses shape.

[TRANSFORM]
Reframe to a formal ID photograph: head-and-shoulders, straight frontal
gaze into the lens, shoulders square, neutral closed-lip expression.

[WARDROBE]  {{preset}}
e.g. black notch-lapel suit jacket over a crisp white dress shirt

[LIGHT]
Studio 3-point: 45-degree key softbox, 1:2 fill ratio, subtle hair light,
soft catchlight in both eyes, no harsh shadow on the background.

[BACKGROUND]
Seamless {{bg_color}} studio paper with a gentle radial falloff.

[LENS]
85mm portrait lens look, f/5.6 depth of field, no wide-angle distortion.

[NEGATIVE]
beauty filter, skin smoothing, plastic skin, airbrushed, anime, oversaturated,
asymmetric eyes, extra fingers, warped glasses frame, text, watermark
```

한국 시장 특유의 주의점: **모델이 기본적으로 "예쁘게" 만들려는 편향(K-beauty 편향)이 강하다.** 실제로 후기에서 "얼굴이 달라져서 못 쓴다"가 가장 큰 이탈 사유다. `Do NOT slim the face / enlarge the eyes`는 옵션이 아니라 **필수**이며, 미화 정도는 사용자가 조절하는 **슬라이더(0~100%)로 노출**하는 것이 옳다.

#### Route B: 개인화 학습(프리미엄 티어)

FLUX LoRA portrait trainer 기준 15~30장 · 2~4시간(RTX 4090 $0.34/h) 또는 호스팅 $2~5/run. FLUX.2 klein은 13GB VRAM에서 학습 가능해 원가가 더 내려간다. 유사도는 가장 높지만 **리드타임과 원가가 대중 상품에 맞지 않는다.**

### S4. 아이덴티티 재주입 — "본인 같음"의 마지막 방어선

생성 결과가 아무리 좋아도 유사도는 항상 떨어진다. 그래서 **생성된 얼굴에 원본 얼굴을 다시 정합**한다.

- 방식: 원본 얼굴 → 생성 얼굴로 아이덴티티 전이 후, 라이팅/색온도/노이즈를 생성 이미지에 맞춰 재조화(harmonization)
- **라이선스 경고(중요):** InsightFace `inswapper_128` 사전학습 가중치는 **비상업 연구용**이다. 상용은 InsightFace와 별도 라이선스 계약 필요. FaceFusion/roop/ReActor 등 다수 오픈 툴이 이 가중치를 쓰므로 **그대로 상용 투입하면 라이선스 위반**이다.
- 상용 대안: ① InsightFace 상용 라이선스 구매 ② 디퓨전 기반 대안(DynamicFace 등) 검토 ③ **S4를 생략하고 S2 어댑터 강도 + S9 게이트로 대체**

> **MVP 권장:** 라이선스 리스크 때문에 **S4는 초기에 생략**하고, 어댑터 강도와 QA 게이트(§S9)로 유사도를 방어한다. 유사도 미달분은 재생성으로 처리한다. 볼륨이 커지면 상용 라이선스를 구매해 S4를 켠다.

### S5. 얼굴 복원 + 업스케일

저화질 셀카 → 인쇄 가능한 300dpi로 올리는 단계. **"사진 퀄리티 업그레이드"의 실체.**

| 모델 | 성격 | 비고 |
|---|---|---|
| **CodeFormer** | VQ 코드북 기반, fidelity-quality 가중치 `w` 조절 가능 | 증명사진은 `w`를 fidelity 쪽으로 (0.5~0.7). 산업 표준 |
| **GFPGAN / GPEN / RestoreFormer++** | StyleGAN prior 계열 | 빠르지만 "일반적인 얼굴"로 수렴하는 경향 → 유사도 손실 주의 |
| **DiffBIR (v2.1)** | SwinIR 열화 제거 + IRControlNet 디퓨전 | NTIRE 2026 실사 얼굴 복원 챌린지 상위 방법들의 백본. https://github.com/XPixelGroup/DiffBIR |
| **HYPIR** | DiffBIR 대비 성능 우위 + 수십 배 빠름 | 2025.07 공개. **비용 민감 서비스에 유력** |
| **SUPIR** | 고품질이나 무겁고 환각 경향 | 증명사진에 비권장 |
| **CodeFormer++** | Deformable registration + deep metric learning. FID 1위, LPIPS 2위 | 2025.10 |

> **함정:** 얼굴 복원은 본질적으로 **생성**이다. 세게 걸수록 예뻐지지만 **본인이 아니게 된다.** 반드시 복원 전/후 ArcFace 유사도를 측정해 `Δcos > 0.05`면 강도를 낮춘 재시도를 건다. 50대 이상 사용자는 특히 주름이 뭉개져 "다른 사람"이 되기 쉽다.

### S6. 리라이팅 + 배경

- **IC-Light** (ICLR 2025, https://github.com/lllyasviel/IC-Light) — 일관된 광수송(light transport)을 강제하는 디퓨전 리라이팅. 배경 조건형(background-conditioned) 모델이 있어 **"이 배경에 맞는 조명"** 합성에 적합. 리라이팅 결과가 노멀맵으로 병합될 만큼 일관적.
- **SynthLight** (2025) — 합성 얼굴 재렌더 학습 기반 인물 리라이팅. 대안으로 검토.
- **매팅/배경 제거** — **BiRefNet** (bilateral reference) 및 그 위에 구축된 **RMBG-2.0**. 머리카락·안경테·소프트 엣지에서 u2net 세대 대비 압도적. 단 RMBG-2.0은 **BRIA 라이선스(상용 시 유료)** 이므로, 상용은 BiRefNet 원본(MIT 계열) 또는 BRIA 상용 계약 중 택일.
  - https://github.com/ZhengPeng7/BiRefNet · https://huggingface.co/briaai/RMBG-2.0
  - 실무 팁: `birefnet-portrait` 가중치가 머리카락 디테일에 유리.
- 배경은 **단색 채우기가 아니라 미세 방사형 그라데이션 + 필름 그레인 1~2%** 를 넣어야 "합성 티"가 사라진다. 이 디테일 하나가 체감 품질을 크게 바꾼다.

### S7. 리터칭 "필터" 레이어 — 체감 품질의 핵심

여기가 **"사진관 같다"의 정체**다. 생성 모델이 만든 이미지는 피부가 지나치게 매끈하거나(플라스틱), 반대로 노이즈가 거칠다. 전문 리터처의 작업을 알고리즘화한다.

1. **주파수 분리(frequency separation)**
   - 저주파: 피부톤·음영 → 가우시안/서페이스 블러로 얼룩·홍조·색조 불균일 정리
   - 고주파: 모공·솜털·잔주름 → **보존**. 여기를 뭉개면 즉시 "AI 티"가 난다
   - 특허/구현 참고: 고주파 경로에 conditional GAN을 쓰는 딥러닝 기반 자동 리터칭 접근이 존재(US 10,593,023)
2. **닷지 & 번(dodge & burn)** — 광대·콧대·턱선 미세 명암으로 입체감 부여
3. **눈/치아** — 공막(sclera) 과백화 금지(즉시 가짜 티). 채도만 -10%, 밝기 +5% 수준
4. **컬러 그레이딩** — 한국 증명사진 관행: 약간 쿨한 화이트밸런스 + 피부 하이라이트 살짝 웜. 프리셋 LUT으로 관리
5. **미세 샤프닝** — 눈/눈썹/입술 라인에만 마스크 샤프닝
6. **그레인** — 1~2% 모노크롬 그레인으로 디지털 평탄함 제거

> **강도 제어:** 모든 항목을 0~1 파라미터로 노출하고, 사용자 "보정 강도" 슬라이더에 매핑한다. 상용 툴(Evoto, Imagen AI 등)이 이 UX를 이미 검증했다.

### S8. 규격화 — 한국 증명사진 스펙

| 용도 | 크기 | 비고 |
|---|---|---|
| 여권 | 35 × 45mm, 머리 길이(정수리~턱) 32~36mm, 머리 위 여백 약 3mm, 흰 배경 | **AI 생성 사진 사용 불가 (§9)** |
| 일반 증명 / 이력서 | 35 × 45mm | 배경: 흰색 / 라이트 그레이 / 블루 |
| 반명함 | 30 × 40mm | |
| 해상도 | 300dpi 이상 → 35×45mm = **413 × 531px** (600×772 권장) | 인쇄 딜리버리 시 |

구현: S1의 정수리/턱/눈 좌표로 **아핀 변환 기반 자동 크롭**. 규격 위반 시 자동 리프레임 후 재검증. OFIQ로 ICAO 관점 컴플라이언스 스코어를 산출해 리포트로 동봉하면 그 자체가 차별화 기능이 된다.

### S9. 자동 QA + 랭킹 — **상업적 핵심**

사용자는 40장 중 5장만 본다. **무엇을 보여주지 않을지가 품질이다.**

```python
# 의사코드: 게이트 → 스코어 → 랭킹
def qa(cand, refs):
    # --- 하드 게이트 (하나라도 실패 시 폐기) ---
    if id_cos(cand, refs) < TAU_ID:            return None   # 유사도
    if faces_detected(cand) != 1:              return None
    if not spec_ok(cand):                      return None   # 규격 크롭
    if artifact_score(cand) > TAU_ART:         return None   # 손가락/안경테 왜곡/비대칭
    if nsfw(cand):                             return None

    # --- 소프트 스코어 (가중 합산) ---
    return (0.40 * id_cos(cand, refs)          # 본인 같음
          + 0.20 * fiqa(cand)                  # 얼굴 이미지 품질
          + 0.15 * aesthetic(cand)             # 심미 예측기
          + 0.15 * spec_score(cand)            # 규격 적합도(OFIQ)
          + 0.10 * expression_neutrality(cand))
```

**임계값 설계 근거**
- ArcFace 코사인 임계값은 운용 FAR에 따라 IJB-B 기준 **0.328(FAR 1e-1) ~ 0.823(FAR 1e-6)** 범위로 보고된다.
- 증명사진은 "타인을 본인으로 오인"보다 **"본인인데 본인 같지 않음"** 이 더 큰 클레임이므로 보수적으로 잡는다. **초기 `TAU_ID = 0.55`(ArcFace/AdaFace 정규화 코사인)** 로 두고, 실사용 클레임률로 튜닝.
- 참조 임베딩은 업로드 전체의 **평균 임베딩(정규화 후)** 을 쓰되, 이상치 1장은 제외.
- AdaFace를 ONNX Runtime으로 병행하면 하드셋에서 +2~4% 개선 보고가 있다.

**다양성 보장:** 상위 5장이 전부 비슷하면 만족도가 떨어진다. 스코어 상위군에서 **의상×배경×헤어 조합이 겹치지 않도록 MMR(Maximal Marginal Relevance) 방식으로 선발**한다.

**재시도 루프:** 합격 후보가 N개 미만이면 어댑터 강도·복원 강도를 조정해 자동 재생성. 이 비용을 원가 모델에 반드시 포함시킨다(재시도율 20% 가정).

## 3. 왜 "사진관에서 찍은 것처럼" 보이는가 — 인지적 근거

사용자가 "사진관 같다"고 느끼는 신호는 얼굴 자체가 아니라 **촬영 환경 신호**다. 이걸 의도적으로 설계해야 한다.

| 신호 | 스냅사진 | 사진관 | 구현 위치 |
|---|---|---|---|
| 광원 | 단일 직사광/형광등, 강한 그림자 | 소프트박스 3점 조명, 부드러운 계조 | S6 |
| 캐치라이트 | 없거나 점 형태 | 양쪽 눈에 사각형 소프트박스 반사 | S3 프롬프트 + S7 |
| 렌즈 | 광각(24~28mm) → 코 확대, 얼굴 왜곡 | 85~105mm → 압축된 자연스러운 비율 | S3 프롬프트 |
| 배경 | 잡다한 실내 | 심리스 페이퍼 + 미세 그라데이션 | S6 |
| 피부 | 유분/홍조/노출 편차 | 톤 균일 + 모공 텍스처 유지 | S7 |
| 의상 | 캐주얼, 주름 | 재킷 어깨선 정돈, 셔츠 칼라 대칭 | S3 |
| 구도 | 임의 | 눈높이가 프레임 상단 40% 지점, 어깨 수평 | S8 |

> **역으로, 이 중 하나만 어긋나도 "AI 티"가 난다.** 특히 ①캐치라이트 없음 ②배경이 완전 단색 ③피부 모공 전멸 — 이 3개가 가장 흔한 실패 신호다.

## 6. 시스템 아키텍처

```
[Web / App]
   │ presigned upload
   ▼
[S3/R2 원본 버킷]  ── KMS AES-256 · 서버측 암호화 · lifecycle 자동 삭제(7일)
   │
   ▼
[API Gateway] ── 주문 생성 · 결제(PG) · 상태 폴링/SSE
   │
   ▼
[Job Queue]  Redis Streams 또는 SQS  (주문 1건 = DAG 1개)
   │
   ├─► [Worker: prep]     CPU  — S0/S1/S2 (수초)
   ├─► [Worker: gen]      GPU  — S3 (배치 N=40, 병렬)
   ├─► [Worker: post]     GPU  — S4~S7
   ├─► [Worker: spec+qa]  CPU/GPU — S8/S9 + 랭킹
   │
   ▼
[결과 버킷] 프리뷰(저해상도+워터마크) / 원본(구매 후 발급)
   │
   ▼
[Notification] 카카오 알림톡 / 푸시 / 이메일
```

**설계 원칙**
- **주문 단위 멱등성(idempotency).** 재시도가 잦은 도메인이므로 각 스테이지는 `(order_id, stage, variant_id)` 키로 멱등 처리.
- **스테이지별 체크포인트 저장.** S3 생성은 비싸므로 후처리 실패 시 재생성하지 않는다.
- **GPU 워커는 스팟 인스턴스 + 큐 깊이 기반 오토스케일.** 유휴 GPU가 이 비즈니스의 최대 원가 누수다.
- **관측성:** 스테이지별 p50/p95 지연, 재시도율, QA 통과율, 유사도 분포를 대시보드화. 유사도 분포가 좌측 이동하면 모델/프롬프트 회귀 신호다.

**데이터 모델(요지)**

```
orders(id, user_id, product, status, created_at, expires_at)
uploads(id, order_id, s3_key, fiqa_score, pose, sharpness, rejected_reason)
identity(order_id, mean_embedding BLOB, n_refs)
variants(id, order_id, preset_id, seed, s3_key, stage_flags)
qa(variant_id, id_cos, fiqa, aesthetic, spec_score, artifact, passed, rank)
deliveries(order_id, variant_id, resolution, watermarked, issued_at)
```

## 8. 서비스 기획

### 8.1 포지셔닝

**"사진관 가지 않아도 되는, 본인처럼 나오는 증명사진"**
— 경쟁축은 *예쁨*이 아니라 **본인 같음 + 시간 절약**이다. 후기에서 반복되는 만족 포인트가 "사진관을 갈 필요가 없어서"였고, 이탈 포인트가 "얼굴이 달라져서"였다.

### 8.2 타겟 세그먼트

| 세그먼트 | 니즈 | 주의 |
|---|---|---|
| 20대 취준생 | 이력서·포트폴리오, 가격 민감 | **공공기관·공기업이 AI 사진 거부 중** → 용도 명확히 고지 필요 |
| 30~40대 직장인 | 링크드인·사내 프로필·명함 | 가장 안전하고 마진 좋은 세그먼트 |
| 50대 이상 | 각종 서류·경조사 | 주름 보존 프리셋 필수. 후기상 만족도 높음 |
| B2B | 기업 임직원 프로필 일괄 촬영 대체 | **실질적 캐시카우 후보** |

### 8.3 상품 구성

| 티어 | 가격 | 내용 | 파이프라인 |
|---|---|---|---|
| 무료 체험 | 0원 | 저해상도 1장 + 워터마크 | Route A, 프리셋 1개 |
| 베이직 | 9,900원 | 시안 20장 → 3장 선택, 고해상도 | Route A |
| 스탠다드 | 19,900원 | 시안 40장 → 5장 선택 + 인쇄용 300dpi + 규격 리포트 | Route A + 전체 후처리 |
| 프리미엄 | 49,000원 | LoRA 개인화 + 시안 100장 + 리터칭 강도 커스텀 | Route B |
| B2B | 별도 | 1인당 단가 × 볼륨, 사내 배경/드레스코드 프리셋 | Route A 배치 |

### 8.4 차별화 기능 (경쟁사 대비 실제 우위 지점)

1. **유사도 점수 공개** — 결과마다 "본인 일치도 92%"를 표시. 경쟁사가 감추는 지표를 자신감으로 전환. (내부 ArcFace 코사인을 사용자 친화 스케일로 변환)
2. **규격 검증 리포트** — OFIQ 기반 "이 사진은 ○○ 규격에 적합/부적합" 자동 판정. 재촬영 비용을 없애는 실질 가치.
3. **AI 사진 사용 가능 여부 가이드** — "여권 ❌ / 이력서 ⚠️ / 링크드인 ✅" 를 제출처별로 안내. **경쟁사 대부분이 회피하는 영역이라 신뢰 차별화가 크다.**
4. **보정 강도 슬라이더** — 0%(무보정)~100%. "AI 티" 공포를 사용자 통제권으로 해소.
5. **재생성 보장** — 유사도 게이트 미달 시 무료 재생성. QA가 있으니 감당 가능한 약속.

### 8.5 퍼널

```
유입(검색/SNS 전후비교) → 무료 1장 체험(가입 없이) → 결과 확인
  → 가입(카카오/애플) → 결제 → 1시간 내 알림톡 → 선택/다운로드
  → 재구매 유도(계절: 취업시즌 3·9월 / 연말 프로필 갱신)
```

전환 핵심은 **"무료 1장을 가입 없이 보여주는 것"**. 얼굴 업로드는 심리 장벽이 높아, 결과를 먼저 보여주지 않으면 결제까지 가지 않는다.

## 9. ⚠️ 법·규제 — 이 사업의 최대 리스크

### 9.1 AI 기본법 (2026-01-22 시행) — **표시 의무**

「인공지능 발전과 신뢰 기반 조성 등에 관한 기본법」 및 시행령이 **2026년 1월 22일 시행**되었다.

- 생성형 AI 산출물(문서·이미지·영상)은 **AI 생성물임을 표시해야 한다.**
- 다운로드·공유 시 **사람이 인식 가능한 방식**(가시적 워터마크 등) 또는 **기계 판독 가능한 방식**(메타데이터 등)으로 표시.
- 실물과 구분이 어려운 가상 콘텐츠(딥페이크류)는 **사람이 명확히 인식 가능한 방식**으로 표시.
- 과기정통부가 「AI 투명성 확보 가이드라인」 등 다수 가이드라인 공개.

**→ 구현 요구사항 (필수, 협상 불가)**

| 항목 | 구현 |
|---|---|
| 기계 판독 표시 | **C2PA Content Credentials** + XMP/EXIF에 `DigitalSourceType = trainedAlgorithmicMedia` 기록. 모든 산출물에 예외 없이 |
| 사람 인식 표시 | 무료/프리뷰: 가시적 워터마크. **유료 산출물은 법무 검토 후 결정** — 증명사진에 가시 워터마크는 사용 불가이므로, "AI 생성물 고지 + 메타데이터" 조합이 적법한지 **법률 자문 필수** |
| 사전 고지 | 생성 전 화면에 "본 결과물은 AI로 생성됩니다" 명시적 동의 |
| 내부 기록 | 주문별 생성 모델·버전·시각을 감사 로그로 보존 |

### 9.2 신분증·공공 제출처 — **AI 사진 사용 불가**

- 주민등록법 시행규칙 등에 따라 신분증(주민등록증·운전면허증·여권) 사진은 **"6개월 이내 촬영한, 모자 등을 쓰지 않은 천연색 상반신 정면 사진"** 이어야 한다. 행정안전부는 **변형이 가능하거나 본인확인이 어려운 사진은 사용 불가**라고 밝혔다.
- 2026년 들어 **공기업·공공기관 채용 공고 상당수에 "AI 증명사진 업로드 불가"가 명시**되고 있으며, 제출 시 불이익 사례가 보도되고 있다("AI 증명사진 내면 탈락입니다").

**→ 서비스 설계 대응**

1. **결제 전** 용도 선택 화면을 강제한다: `여권/신분증(❌ 불가)` / `공공기관 채용(⚠️ 확인 필요)` / `일반 이력서·프로필(✅)`
2. 여권/신분증 선택 시 **판매하지 않고 안내로 종료**. 단기 매출보다 클레임·환불·평판 리스크가 크다.
3. 이용약관에 용도 제한과 면책을 명시하되, **약관만으로 방어되지 않는다**는 전제로 UX에서 차단한다.
4. 이 리스크를 **역이용**: §8.4의 "제출처별 사용 가능 여부 가이드"는 경쟁사가 회피하는 영역이라 오히려 신뢰 자산이 된다.

### 9.3 개인정보 — 얼굴은 민감정보

- 얼굴 이미지로부터 생성한 특징점/임베딩은 개인정보보호법상 **생체인식정보(민감정보)** 에 해당할 수 있다. 별도 동의·목적 제한·안전조치가 요구된다.
- 필수 조치
  - 수집 최소화: 필요한 장수만, 업로드 원본은 **결과 생성 후 7일 내 자동 파기**(lifecycle 정책)
  - **얼굴 임베딩은 주문 종료 시 즉시 삭제**. 장기 보관하지 않는다
  - 저장 시 암호화(AES-256, KMS 키 분리), 접근 로그, 최소권한
  - **"업로드 사진을 모델 학습에 사용하지 않음"을 약관·개인정보처리방침에 명시**하고 실제로 지킨다. 이 한 줄이 전환율에 직접 기여한다
  - 국외 이전: 생성 API가 해외 리전이면 **국외 이전 고지·동의** 필요. 자체호스팅 전환의 또 다른 이유
- 미성년자 업로드 차단(연령 확인), 타인 사진 업로드 금지 고지 및 신고 창구

### 9.4 초상권·악용 방지

- 본인 사진만 업로드하도록 약관에 명시하고, 업로드 시 체크박스 동의
- 유명인 얼굴 차단 리스트(선택), 생성물 전량 C2PA 서명으로 사후 추적 가능성 확보
- NSFW/딥페이크 전용 차단: 증명사진 도메인이라 프롬프트가 고정되어 있어 리스크는 낮지만, 업로드 이미지 자체의 NSFW 검사는 필요
