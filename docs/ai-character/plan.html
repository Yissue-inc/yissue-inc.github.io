사람 없이 연기하는 캐릭터를 만든다

유니버설의 동키 미트앤그리트는 숨은 성우가 실시간으로 연기하는 인터랙티브 퍼펫이다. 이 문서는 그 성우가 하는 일 — 듣고, 보고, 알아채고, 받아치고, 웃기고, 표정과 시선으로 연기하는 것 — 을 하나씩 분해해 AI 파이프라인으로 대체하는 전체 수행 계획이다. 첫 MVP는 토이스토리 버즈 1인 대면 키오스크, 목표 기간 17주.

시작 전에 정리해야 할 권리 문제

기술보다 먼저 막히는 지점이다. 여기가 안 풀리면 만든 걸 켤 수 없다.

먼저 확인

버즈 라이트이어·우디는 디즈니/픽사의 저작물이고, 원작 목소리는 배우 개인의 음성·퍼블리시티권 대상이다. 이 둘은 별개의 권리라 라이선스도 따로 받아야 한다. 배우 목소리를 그대로 학습·복제한 TTS는 라이선스가 있어도 별도 동의 없이는 쓸 수 없다.

따라서 처음부터 두 갈래를 병렬로 잡는다. 기술 스택은 어느 쪽이든 동일하고, 바뀌는 것은 persona pack 하나뿐이다 — 이 구조를 3장에서 아키텍처의 최상위 원칙으로 못 박는다.

트랙용도필요한 것착수
A. 토이스토리 트랙디즈니 대상 제안·PoC 시연, 라이선스 협상용비공개 내부 시연 한정. 배우 목소리 복제 금지, 사운드얼라이크 성우와 별도 계약(학습·상업 이용 명시)W1
B. 오리지널 트랙공개 시연·투자 유치·자체 IP 상품화자체 캐릭터 디자인·보이스·세계관. 권리 100% 자사 귀속W2

실무적으로는 B를 기술 검증의 기본 트랙으로 두고, A는 데모 빌드로만 유지하는 편이 안전하다. 성능 지표(지연·웃음률·인식률)는 캐릭터와 무관하게 측정되므로 검증 가치는 동일하다.

추가로 초기에 확정할 것: 관람객 영상·음성의 수집·보관 정책(6장), 미성년자 촬영 고지, 국내 배치 시 개인정보 보호법상 영상정보처리기기 안내판 의무.

01

동키는 실제로 무엇을 하고 있나

성우 한 명이 동시에 처리하는 작업을 항목으로 쪼개면, 그대로 개발 백로그가 된다.

동키 부스의 성우는 카메라로 관람객을 보면서 실시간으로 대사를 만들고, 동시에 퍼펫의 입과 표정을 조작한다. 관람객이 "살아있다"고 느끼는 이유는 목소리 품질이 아니라 반응 속도와 관찰의 구체성이다. 내 모자 색을 언급하고, 3턴 전에 말한 내 이름을 다시 부른다. 이 두 가지가 없으면 아무리 좋은 TTS도 자판기처럼 들린다.

설계 결론

표에서 상으로 분류된 네 항목 — 바지인, 타이밍, 수위 조절, 예외 대응 — 이 프로젝트의 실제 난이도다. 목소리 합성과 3D 렌더링은 이미 상용 부품으로 해결되는 영역이므로, 인력과 일정을 여기에 쏟지 않도록 스프린트를 배치했다(8장).

대사 생성 프롬프트 구조

시스템 프롬프트는 고정 블록(캐시)과 가변 블록을 분리해 매 턴 캐시 적중을 노린다. 고정 블록은 세션 내내 바이트 단위로 동일해야 한다.

# 고정 블록 (프롬프트 캐시 대상, 약 3k 토큰)
  1. 정체성      캐릭터가 자신을 어떻게 인식하는지, 무엇을 모르는지
  2. 말투 규칙   문장 길이 상한, 어미, 금지 어휘, 캐치프레이즈 사용 빈도
  3. 세계관 사실 캐릭터가 아는 것 / 절대 모르는 것(현실 세계 지식 차단)
  4. 유머 규칙   웃음 소스 4종과 사용 조건, roast 강도 정의(5장)
  5. 금칙        주제·표현 블랙리스트, 회피 대사 30종(인 캐릭터)
  6. 출력 계약   perform 이벤트 JSON 스키마와 필드 제약

# 가변 블록 (매 턴 갱신, 약 300~500 토큰)
  7. 장면 요약   scene.summary 최신값
  8. 세션 메모리 이름·언급된 사실·이미 쓴 농담 목록(재사용 금지)
  9. 최근 3턴   관람객 발화와 캐릭터 대사
 10. 상황 신호  대기줄 길이, 세션 경과 시간, 남은 시간

중요한 제약 하나

대사 길이 상한을 문장 2개·40자 내외로 강제한다. 모델은 놔두면 길게 말하고, 길어지는 순간 대화가 아니라 안내방송이 된다. 짧은 대사는 지연·비용·처리량 세 지표를 동시에 개선한다.

체감 지연을 절반으로 줄이는 세 가지

  1. 즉시 백채널. 발화 종료를 감지한 순간(≈180 ms) 사전 녹음된 짧은 반응 — "오?", "잠깐만", 숨 들이키는 소리 — 을 무조건 재생한다. 본 대사가 준비되면 자연스럽게 이어 붙인다. 체감 반응 시간이 0.9초에서 0.3초대로 떨어진다.
  2. 생각하는 연기. 백채널과 동시에 고개를 살짝 기울이거나 눈을 굴리는 아이들 클립을 재생한다. 사람은 상대가 "생각 중"이라는 신호를 받으면 기다림을 지연으로 인식하지 않는다.
  3. 문장 단위 파이프라이닝. LLM 출력이 끝날 때까지 기다리지 않고 첫 문장 경계에서 TTS를 시작한다. 두 번째 문장은 첫 문장이 재생되는 동안 합성된다.

계측 원칙

모든 스테이지는 이벤트에 ts_in·ts_out을 찍는다. 지연은 추정하지 않고 세션 단위 히스토그램으로만 이야기한다. P50이 아니라 P95를 회의 지표로 쓴다 — 평균이 좋아도 20세션 중 1번 멈추면 실패다.

05

유머 엔진

이 프로젝트의 유일한 차별점이자 가장 어려운 부분. "재밌게 해줘"라고 프롬프트에 쓰는 것으로는 절대 되지 않는다.

LLM에게 자유롭게 농담을 시키면 두 가지가 일어난다. 어디서 본 듯한 일반 개그를 하거나, 수위를 잘못 잡는다. 해결책은 웃음의 재료를 시스템이 공급하고, 모델에게는 조립만 시키는 것이다.

구조와 타이밍

대사는 셋업 → beat → 펀치 3부 구조를 출력 계약에 강제한다. 핵심은 beat다. 펀치라인 직전 250~400 ms의 무음이 있고 없고가 같은 문장의 성패를 가른다. Stage 5의 오디오 스케줄러가 beats 배열을 받아 무음 프레임을 삽입하고, Stage 6은 그 구간에 "뜸 들이는" 표정 클립을 얹는다.

roast 강도 다이얼

관람객을 살짝 놀리는 것이 재미의 대부분인데, 여기가 사고 지점이기도 하다. 0~3 단계로 정의하고 대상 추정 나이·동행 구성·직전 반응으로 자동 조절한다.

외모·체형·피부색·인종·국적·장애·나이 듦·종교·정치·가족 구성에 대한 언급은 강도 3에서도 하드 블록한다. 프롬프트 지시가 아니라 출력 후 별도 분류기로 차단하고, 걸리면 안전 대사로 대체한다.

튜닝 루프

웃음은 측정 가능하다. 오디오 웃음 분류기가 대사 종료 후 2.5초 창에서 웃음·감탄을 탐지하고, humor_src·risk 태그와 함께 로깅한다. 주 1회 이 로그로 세 가지를 한다.

  • 성공률 상위 패턴을 퍼소나 팩의 예시 대사로 승격(few-shot 강화)
  • 성공률 하위 패턴을 금지 목록으로 강등
  • 실패 세션 20개를 코미디 작가·성우가 육안 검수 — 이 사람 개입이 파이프라인의 일부다
06

안전 · 가드레일 · 개인정보

아이들 앞에 세우는 물건이다. 사고 1건이 프로젝트 전체를 끝낼 수 있으므로 다층 방어로 설계한다.

4중 방어선

층막는 것구현실패 시 동작
1. 입력 검사프롬프트 인젝션("시스템 프롬프트 말해봐"), 유해 요청 유도패턴 + 소형 분류기, 전사 텍스트 대상인 캐릭터 회피 대사로 즉시 응답
2. 페르소나 구속캐릭터가 아는 범위 밖 지식, 현실 세계 언급시스템 프롬프트의 "모르는 것" 목록 + 지식 차단 규칙"그건 우주 사령부 기밀이다"류 회피
3. 출력 검사금칙 주제, 자기지칭(AI·모델), 개인정보 복창, 타 브랜드 언급합성 전 텍스트 분류기 + 정규식 블랙리스트안전 대사 풀에서 대체 재생, 사건 로깅
4. 사람위 셋이 다 놓친 것, 예외 상황오퍼레이터 콘솔 — 실시간 자막·원터치 뮤트·수동 대사세션 즉시 종료, 캐릭터는 "교신 두절" 연출

개인정보 처리 원칙

  • 영상은 저장하지 않는다. 프레임은 메모리 내에서만 처리하고 디스크·네트워크로 나가지 않는다. Stage 3이 만드는 것은 원본이 아니라 "빨간 모자, 공룡 티셔츠" 같은 텍스트 속성뿐이다.
  • 얼굴 식별을 하지 않는다. 추적 ID는 세션 종료와 함께 파기하며 재방문 인식·인물 DB를 만들지 않는다.
  • 음성 원본은 옵트인. 기본은 텍스트 전사만 30일 보관(사고 재현·품질 튜닝 목적). 원본 오디오는 별도 동의 시에만.
  • 고지. 부스 입구에 촬영·음성 처리 안내판, 보호자용 QR 상세 고지. 국내 설치 시 영상정보처리기기 안내 의무 충족.
  • 미성년자. 나이 추정은 어투 조절 목적으로만 쓰고 저장·전송하지 않는다.

예외 시나리오 팩

퍼소나 팩에 미리 작성해 두는 대응 대본. 모델이 즉흥으로 처리하게 두지 않는다.

  • 아이가 울음 → 즉시 강도 0, 목소리 톤 다운, 보호자 쪽으로 시선 전환
  • 욕설·성적 발언 → 못 들은 척 화제 전환 1회 → 반복 시 세션 종료 신호
  • "너 사람이야? AI야?" → 인 캐릭터 회피(캐릭터는 자기가 진짜라고 믿음)
  • 침묵 8초 → 먼저 말 걸기 1회 → 15초 → 마무리 대사 후 세션 종료
  • ASR 연속 실패 3회 → "통신 상태가 안 좋군" + 오퍼레이터 알림
  • 시스템 장애 → 사전 녹음 루프 재생 + 콘솔 경보 (관람객은 눈치채지 못하게)
07

MVP: 버즈 라이트이어 1인 대면 키오스크

17주 안에 "살아있다"는 반응을 받아내는 것이 목표. 그 외 모든 욕심은 2차로 미룬다.

왜 우디가 아니라 버즈인가

  • 즉흥 구조가 이미 캐릭터에 내장돼 있다. 자신을 진짜 우주 레인저라고 믿는 설정 자체가 개그 엔진이다. 관람객이 "너 장난감이잖아"라고 말하는 순간 캐논 유머가 자동으로 발동한다 — 모델이 창의적일 필요가 없다.
  • 말투가 규칙화하기 쉽다. 군대식 짧은 문장, 보고 형식, 고정 캐치프레이즈. 40자 제한과 궁합이 좋고 캐릭터 붕괴 판정도 쉽다.
  • 립싱크가 관대하다. 딱딱한 플라스틱 재질의 단순한 입 모양이라 비지메 오차가 눈에 덜 띈다. P2 리스크를 크게 줄인다.
  • 모르는 게 자연스럽다. 현실 세계 지식을 차단해야 하는데(6장), 버즈는 원래 세상 물정을 모른다. 가드레일이 캐릭터성으로 위장된다.

우디는 P4 이후 두 번째 퍼소나 팩으로 추가해 팩 교체 구조를 검증하는 용도로 쓴다.

범위에 포함

  • 1:1 대면(동행 1명까지 인지, 대화 상대는 1명)
  • 한국어 주 언어 + 영어 인식·응답
  • 세션 90초, 유효 6턴 이상
  • 세로형 대형 디스플레이 + 실시간 3D 렌더
  • 유머 소스 2종(관찰·캐논)
  • 시선 추적, 표정, 상반신 제스처
  • 오퍼레이터 상주 운영
  • 4중 가드레일 전부

범위에서 제외 (2차 이후)

  • 애니매트로닉스·물리 퍼펫
  • 다인 동시 대화, 그룹 진행
  • 캐릭터 이동·전신 보행
  • 사진 촬영·굿즈·앱 연동
  • 무인 운영(오퍼레이터 제거)
  • 다국어 3개 이상
  • 재방문 인식(개인정보 원칙상 영구 제외)

MVP 수용 기준

아래 7개를 사내 관람객 100명 연속 테스트에서 모두 만족하면 MVP 완료로 선언한다.

08

17주 로드맵

각 페이즈는 게이트로 닫힌다. 게이트를 통과하지 못하면 다음 페이즈를 시작하지 않고 범위를 줄인다 — 일정을 늘리는 것보다 스코프를 깎는 쪽이 항상 낫다.

P0 · W1–W2

기반 다지기

권리 트랙 확정, 성공 지표 계측 방법 합의, 하드웨어 발주. 코드를 쓰기 전에 되돌릴 수 없는 결정부터 끝낸다.

  • 권리 트랙 A/B 결정 및 성우 후보 오디션(사운드얼라이크 계약 조건 포함)
  • KPI 10개의 측정 코드 정의 — 측정할 수 없는 지표는 이 시점에 버린다
  • GPU 워크스테이션·카메라·마이크 어레이 발주(리드타임 4~6주 가정)
  • 퍼소나 팩 스키마 확정 — 이후 모든 캐릭터 자산이 이 형식을 따른다
  • 현장 소음 실측: 배치 예정 공간에서 dBA 프로파일과 잔향 녹음 확보
GATE — 권리 트랙 문서화 + 지표 정의 코드 머지 + 발주 완료
P1 · W3–W6

대화 코어

화면도 3D도 없다. 노트북 + 헤드셋으로 '말이 되는 대화'만 만든다. 여기서 재미가 안 나오면 아바타를 붙여도 안 난다.

  • ASR·LLM·TTS 왕복 스트리밍 연결, 문장 단위 파이프라이닝 구현
  • 퍼소나 팩 v1: 정체성·말투·세계관·금칙·회피 대사 30종 작성(성우/작가 참여)
  • 지연 계측 하네스 — 구간별 ts_in/ts_out 히스토그램 대시보드
  • 구간별 벤치마크 3종(ASR·LLM·TTS) 실행 후 1순위 스택 확정
  • 세션 메모리 슬롯과 콜백 규칙 구현
  • 입력·출력 가드레일 1차, 안전 대사 폴백 경로
GATE — 헤드셋 블라인드 테스트 10명 중 7명이 '사람 같다'고 답할 것 + 지연 P95 ≤ 1.5 s
P2 · W7–W10

실시간 아바타

목소리에 몸을 붙인다. 60 fps를 놓치지 않는 것이 이 페이즈의 유일한 하드 요건이다.

  • UE5 프로젝트 셋업, 스타일라이즈드 캐릭터 리그 + ARKit 호환 블렌드셰이프
  • 오디오→비지메 립싱크, 동기 오차 ±40 ms 이내 검증
  • 감정 태그 → 표정 매핑, 마이크로 표정·눈깜빡임 절차 생성
  • 시선 look-at IK, 아이들 행동 트리(대기·주목·반응·작별)
  • 바지인: 관람객이 말을 끊으면 발화 중단 후 자연스럽게 회복하는 상태머신
  • beat 오디오 스케줄러 + 뜸 들이는 표정 클립
GATE — 60 fps 고정 30분 무드랍 + 립싱크 육안 검수 통과 + 바지인 20회 중 실패 0
P3 · W11–W14

인지와 유머

관람객을 '보기' 시작한다. 프로젝트의 차별점이 여기서 만들어지고, 실패 위험도 여기 몰려 있다.

  • 카메라 파이프라인: 검출·추적·재식별, 깊이 기반 신장 추정
  • 화자 지정: 마이크 도래각 + 입 움직임 융합
  • VLM 장면 요약 2 fps, 원본 프레임 미저장 경로 검증
  • 유머 엔진 v1 — 관찰·캐논 2소스, 셋업/beat/펀치 출력 계약 강제

운영 원가

"세션 하나에 얼마인가"는 사업성을 가르는 숫자다. 단가는 벤더·환율에 따라 바뀌므로 계산식을 고정하고 단가만 갈아끼운다.

기준 세션: 90초, 관람객 발화 8턴, 캐릭터 대사 8회(평균 40자).

구간세션당 사용량계산식추정 (USD)
ASR 스트리밍1.5분 오디오분당 단가 × 1.50.009
VLM 장면 요약크롭 4회 × 요약 200토큰(이미지 + 출력) × 40.012
LLM 대사 생성8턴 × (캐시 3k + 신규 0.4k 입력 / 0.09k 출력)캐시 읽기 단가 적용이 핵심0.030
TTS 합성8회 × 40자 = 320자문자당 단가 × 3200.034
가드레일 분류입력 8 + 출력 8회소형 모델 또는 로컬0.004
세션당 합계≈ 0.089

환산 약 120원/세션. 일 10시간 × 시간당 28세션 = 280세션 기준 일 3.4만 원, 월 약 100만 원. 키오스크 1대 기준으로 운영비는 사실상 인건비(오퍼레이터)가 지배한다.

원가를 줄이는 순서

  1. 프롬프트 캐싱을 먼저 확실히 한다. 고정 블록 3k 토큰이 매 턴 캐시 미스면 LLM 비용이 3~4배가 된다. 고정 블록의 바이트 불변성을 테스트로 강제한다.
  2. 캐치프레이즈는 합성하지 않는다. 반복 대사 상위 30개를 사전 녹음으로 대체하면 TTS 문자 수가 30~40% 줄고 품질과 지연도 같이 좋아진다.
  3. ASR·비전을 온프레미스로 내린다. GPU가 이미 렌더용으로 상주하므로 유휴 자원을 쓰는 셈이다. 지연도 함께 개선된다.
  4. VLM 호출을 이벤트 기반으로. 매 프레임이 아니라 새 인물 진입·복장 변화 시에만 호출한다.

주의

위 단가는 문서 작성 시점의 일반적 수준을 가정한 추정치다. 예산 확정 전 각 벤더의 현재 요금표로 이 표를 다시 채워야 한다.

착수: 저장소 구조와 첫 2주

문서를 승인한 다음 날 아침에 시작할 수 있는 형태로 정리한다.

저장소 구조

스테이지 = 프로세스 = 디렉터리로 1:1 대응시킨다. 어떤 스테이지든 혼자 죽고 혼자 재시작할 수 있어야 한다.

toybox-live/
├─ apps/
│  ├─ orchestrator/   세션 상태머신, 이벤트 버스, 지연 계측
│  ├─ perception/     카메라·추적·신장 추정·VLM 요약        (Stage 1,3)
│  ├─ voice/          AEC·빔포밍·VAD·ASR·TTS·beat 스케줄러  (Stage 2,5)
│  ├─ brain/          퍼소나 LLM·유머 엔진·메모리·가드레일   (Stage 4)
│  ├─ stage/          UE5 프로젝트: 리그·립싱크·행동 트리    (Stage 6,7)
│  └─ console/        오퍼레이터 웹 콘솔(자막·뮤트·수동 대사)

└─ docs/                본 기획서, 결정 기록(ADR), 실측 데이터

설계 원칙 세 줄

1. 스테이지는 protocol 이벤트로만 대화한다 — 직접 함수 호출 금지.
2. 캐릭터에 종속된 모든 것은 persona/ 안에 있다 — 코드에 캐릭터 이름이 등장하면 설계 위반.
3. 측정할 수 없는 기능은 만들지 않는다 — eval/에 판정 코드가 없으면 완료가 아니다.

첫 2주 체크리스트 (P0)

  • 권리 트랙 A/B 결정 회의 — 법무 검토 의견 첨부리드 · 법무
  • 사운드얼라이크 성우 오디션 공고 (학습·상업 이용 조건 명시)리드
  • 배치 예정 공간 소음 실측 — dBA 프로파일 + 잔향 녹음 30분오디오
  • KPI 10개 측정 정의 문서화 + eval 스켈레톤 커밋대화
  • protocol 이벤트 스키마 v0 확정 (utterance / scene / perform)대화 · 비전
  • 퍼소나 팩 디렉터리 스키마 확정 + 빈 buzz 팩 생성대화
  • GPU 워크스테이션 · 마이크 어레이 · 카메라 발주하드웨어
  • ASR·TTS 벤더 3곳 평가 계정 개설 및 단가표 확보오디오
  • 버즈 톤 레퍼런스 수집 — 원작 대사 100개 분해, 말투 규칙 초안작가

  • P1 게이트 판정 방법 합의 — 블라인드 테스트 프로토콜 문서화리드 · QA
  • 주간 리듬 확정: 월 스탠드업 / 금 회귀 측정 + 로그 검수 30세션전원

결정이 필요한 사항

진행 전 확답이 필요한 세 가지다. 나머지는 기본값으로 진행 가능하다.

  1. 권리 트랙. 토이스토리를 내부 데모로만 쓰고 오리지널 캐릭터를 병행할 것인가, 아니면 처음부터 디즈니 라이선스 협상을 전제로 갈 것인가.
  2. 배치 목표. 최종 설치처가 테마파크인가, 전시·팝업인가, 리테일 매장인가. 소음·조도·체류시간이 달라 하드웨어 사양이 바뀐다.
  3. 인력 조달. 5.5 FTE를 내부에서 채울지 외부 조달할지에 따라 예산이 1억과 3.3억으로 갈린다.
