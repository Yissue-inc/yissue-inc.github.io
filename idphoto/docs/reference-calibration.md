# 레퍼런스 실측 — 인핸즈 입출력 기반 보정

측정일 2026-09-13 · 자료: 사용자 제공 입력 셀카 3장 + 인핸즈 출력 2장
사진은 `samples/private/`(gitignore)에 있고 저장소에 커밋되지 않는다 — 얼굴은 민감정보다.

**표본은 1인이다.** 여기서 확정한 값은 한 사람의 데이터에 근거하므로, 사용자가
늘어나면 재보정해야 한다. 그럼에도 추측으로 잡았던 이전 값보다는 훨씬 낫다.

---

## 1. 발견한 버그 — 실사진이 아니었으면 못 잡았다

### 1.1 YuNet 이 큰 이미지에서 무너진다 (치명)

| 입력 긴 변 | 검출 점수 | 같은 사람 2장의 SFace 유사도 |
|---|---|---|
| 원본 2576px | 0.633 | **0.012** |
| 1600px | 0.918 | **0.830** |
| 640px | — | 0.799 |

랜드마크가 부정확해지면 SFace `alignCrop` 이 얼굴을 잘못 정렬하고 임베딩이 통째로
망가진다. **요즘 휴대폰 사진은 3000~4000px 이므로 실사용 업로드는 거의 전부 이
구간에 들어간다.** 합성 테스트로는 절대 발견할 수 없었다 — 테스트 이미지가 작았다.

여파는 임베딩만이 아니었다:

| | 수정 전 | 수정 후 |
|---|---|---|
| 입력 3장 상호 최소 유사도 | 0.013 | **0.547** |
| in3 포즈 | yaw +0.182 / pitch **+0.200** | yaw −0.046 / pitch −0.002 |
| in2 얼굴 크기 | 606px | 1017px |

`pitch +0.200` 은 게이트 거절선(0.16)을 넘는다. **정면으로 잘 찍은 사진이 버그
때문에 거절당하고 있었다.**

수정: 검출은 긴 변 1280px 축소본에서 하고 좌표만 원본 스케일로 되돌린다.
정렬·크롭·리터칭은 원본 해상도에서 이루어지므로 화질 손실이 없다.

### 1.2 배경 샘플링이 아래쪽 모서리를 본다

제대로 구도가 잡힌 증명사진은 어깨가 하단 가장자리까지 닿는다. 아래 모서리에
있는 것은 배경이 아니라 **옷**이다.

| 샘플링 범위 | 배경 일관성 (허용 26) |
|---|---|
| 네 모서리 전부 | **116** — 추정 실패 |
| 위쪽 모서리만 | **0.0 ~ 0.5** — 완벽 |

매팅이 실패하면 머리카락 최상부를 못 잡아 두개골 추정값으로 폴백하고, 크롭 신뢰도가
떨어진다. 수정 후 세 장 모두 `crown_source=matte` 로 복구됐다.

### 1.3 피부톤 게이트가 L\*(밝기) 기준이었다

인핸즈 출력은 입력 대비 **ΔL\* +29** 다. 실내 셀카를 스튜디오 조명으로 다시
비추면 당연한 일이고, 사용자도 그 결과를 만족스럽게 쓰고 있다. 기존 `ΔL* ≤ 4.0`
게이트였다면 **정상 생성물이 전부 탈락**했다.

같은 측정에서 채도 좌표는 거의 그대로였다: **Δa\* +0.0, Δb\* +3.0**.

> 밝기는 조명이 정하고, **색조는 사람이 정한다.**

게이트를 `sqrt(Δa*² + Δb*²) ≤ 9.0` 으로 바꿨다. 인핸즈 출력 실측 4.1~4.5 로
여유 있게 통과한다. ΔL\* 은 극단적 표백만 잡는 넓은 상한(45)으로 남겼다.

## 2. 확정한 임계값

### 유사도 (SFace 코사인)

| 기준 | 값 |
|---|---|
| OpenCV 동일인 판정 레퍼런스 | 0.363 |
| **같은 사람의 다른 실사진 2장 (최악)** | **0.547** ← 자연 하한 |
| **인핸즈 출력 vs 참조 평균** | **0.646 ~ 0.674** ← 경쟁 기준선 |
| 인핸즈 출력 2장끼리 | 0.946 |

같은 사람을 다른 날 찍어도 0.547 밖에 안 나온다. 생성물에 그보다 높은 값을
요구하는 것은 무의미하다.

- `tau_id = 0.50` (하드 게이트)
- `tau_id_target = 0.65` (인핸즈 수준)

이전 값 0.42 는 근거 없는 추측이었고 너무 느슨했다.

### 검증

우리 QA 게이트에 인핸즈 출력을 넣으면:

| | 유사도 | Δchroma | 종합점수 | 판정 |
|---|---|---|---|---|
| enhanz_small | 0.674 | 4.5 | 0.754 | 통과 |
| enhanz_large | 0.646 | 4.1 | 0.824 | 통과 |

사용자가 실제로 만족하며 쓰는 결과물이 통과한다 — 게이트가 현실적으로 조정됐다는 뜻이다.

## 3. 인핸즈 출력 특성 (우리 목표치)

### 크롭 기하

| | 머리카락 여백 | 머리 길이 (hair) | 머리 길이 (skull) | 눈높이 | 얼굴 중심 x |
|---|---|---|---|---|---|
| enhanz_small (413×531) | 3.1mm | 34.4mm | 30.8mm | 46.3% | 50.0% |
| enhanz_large (1792×2304) | 3.8mm | 29.3mm | 26.6mm | 41.8% | 50.9% |

- **413×531 px** — 35×45mm @300dpi 계산값과 정확히 일치. 외교부 온라인 신청 권장 규격과도 같다.
- 얼굴 중심이 정확히 프레임 중앙(50.0%), roll −0.24° — 수평 정렬이 정밀하다.
- 머리카락 최상부와 두개골 최상부가 **2.5~3.5mm 차이** — 이중 측정 설계가 실제로 필요했음이 확인됐다.

> **규격 주의**: 외교부 여권 규정의 머리 길이(머리카락 제외 32~36mm)를 기준으로 재면
> enhanz_small 은 30.8mm 로 **규격 미달**이다. 머리카락 포함으로 재면 34.4mm 로 규격 내다.
> 우리 구현은 규정 문언(머리카락 제외)을 따르므로 인핸즈보다 엄격하다. 여권용은 어차피
> AI 생성물 제출이 불가하므로 실무 영향은 없으나, 규격 리포트 문구에 반영할 것.

### 배경

- 좌우 가장자리 L\* 세로 프로파일: **252~254 로 거의 평탄** (어깨선 아래는 옷)
- a\*, b\* 편차 **+0.0, +1.0** — 사실상 순수 무채색 흰색
- **방사형 그라데이션이 거의 없다.** 우리 `studio_backdrop` 기본값(`light_gray`, edge=0.90)은
  실측 대비 그라데이션이 과하다 — 평탄한 쪽으로 조정 필요.

### 피부 / 질감

| | L\* | a\* | b\* | 고주파 | 피부 밝기 표준편차 |
|---|---|---|---|---|---|
| 입력 (in1) | 46.3 | +12.0 | +15.0 | 3.70 | 46.7 |
| 인핸즈 출력 | 75.3 | +12.0 | +18.0 | **4.66** | **27.0** |

- **고주파가 오히려 증가**(3.70 → 4.66). 인핸즈는 질감을 뭉개지 않는다 — 우리 설계 방향과 일치.
- 피부 밝기 표준편차 46.7 → 27.0. 톤을 크게 균일화했다(스튜디오 조명 효과).
- 붉은기(a\*)를 건드리지 않았다. 우리 `reduce_redness` 기본값을 낮춰야 할 근거다.

## 4. 남은 재보정 대상

- 표본이 1인이다. 연령·성별·피부톤별로 최소 수십 명이 모이면 전면 재보정.
- 잡티 검출은 이 사진들로 아직 평가하지 않았다 (실제 잡티 진리값이 없음).
- `studio_backdrop` 그라데이션 강도를 실측(평탄)에 맞춰 조정해야 한다.
- `reduce_redness` 기본값이 인핸즈 대비 과하다.
