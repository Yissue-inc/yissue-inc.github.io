## 0. 한 문단 요약

셀카 몇 장으로 증명사진을 만드는 파이프라인. **코드는 완성돼 있고 사용자 실제
사진으로 검증됐습니다.** 남은 것은 **생성 API 호출 한 번**뿐입니다 — 클라우드
세션에서는 Gemini 키에 닿을 수 없어 그 한 걸음만 막혀 있었습니다. 로컬에는
`ai_keys.py` 와 키가 있으므로 바로 됩니다.

목표는 **인핸즈(enhanz.io) 품질을 수치로 넘어서는 것**이고, 그 기준선은
추측이 아니라 사용자가 제공한 인핸즈 입출력을 실측해서 잡았습니다: **유사도 0.646~0.674**.

## 1. 지금 당장 할 일

```bash
cd idphoto
pip install -r requirements.txt
./scripts/fetch_models.sh          # Apache-2.0 모델 3종, ~43MB
export PYTHONPATH=src

python3 -m idphoto doctor          # 모델·의존성·API 인증 점검 (무과금)
```

`doctor` 가 전부 ✓ 면 파일럿:

```bash
python3 <ai_keys 경로>/ai_keys.py run gemini \
  --purpose "AI 증명사진 3x3 교차 파일럿" --est-usd 0.74 \
  --model gemini-3.1-flash-image \
  -- python3 -m idphoto run <입력사진 3장> --provider gemini \
     --models gemini-3-pro-image,gemini-3.1-flash-image,gemini-3.1-flash-lite-image \
     --variants baseline,lock,measured \
     --spec id_kr --n 9 --present 3 --out out/pilot
```

**9장 = 3모델 × 3프롬프트 완전 교차.** 공시가 **$0.738** — 프로토콜 §4 자동 구간($1) 이내.

끝나면 요약의 `usage` · `est_usd_next_run` 이 **실측 단가**입니다. 다음 배치는 그 값으로
`--est-usd` 를 채웁니다. 추측 금액 금지(프로토콜 §4).

### 파일럿에서 봐야 할 것

1. **모델별·프롬프트별 유사도 표** — 어느 조합이 0.646 을 넘는가
2. **정장 변환 품질** (육안) — mock 으로는 확인 불가능했던 유일한 부분
3. **탈락 사유 분포** — 어느 게이트가 실제로 걸리는가
4. **실측 단가** — 40장 배치 원가 재계산의 근거

## 2. 합격선 — 전부 실측값

| 기준 | 값 | 의미 |
|---|---|---|
| OpenCV SFace 동일인 판정 | 0.363 | 레퍼런스 구현 임계값 |
| 같은 사람의 다른 실사진 2장 (최악) | **0.547** | 자연 하한 — 이보다 높게 요구해도 의미 없음 |
| **인핸즈 출력 vs 참조 평균** | **0.646 ~ 0.674** | **넘어야 할 선** |
| 인핸즈 출력 2장끼리 | 0.946 | 같은 생성 배치의 일관성 |
| 우리 하드 게이트 | 0.50 | `config.py: tau_id` |
| 우리 목표 | 0.65 | `config.py: tau_id_target` |

검증: 인핸즈 출력 2장을 우리 QA 게이트에 넣으면 종합점수 **0.754 / 0.824 로 통과**합니다.
게이트가 현실적으로 조정돼 있다는 뜻입니다.

기타 실측 기준선:
- 인핸즈 크롭: 413×531px, 머리 30.8mm(두개골 기준), 눈높이 46.3%, 얼굴 중심 50.0%
- 인핸즈 배경: L\* 252~254 **거의 평탄**, a\*/b\* +0.0/+1.0 (순백 무채색)
- 인핸즈 피부: ΔL\* **+29**(조명), Δa\* **+0.0**(붉은기 유지), 고주파 3.70 → **4.66 (증가)**

## 4. 설계 결정과 이유

새 세션이 "왜 이렇게 했지?" 하고 되돌릴 만한 것들입니다. **되돌리지 마세요.**

### InsightFace 를 쓰지 않는다
코드는 MIT 지만 **`buffalo_l` 을 포함한 모든 사전학습 모델이 비상업 연구용**입니다
(upstream README §License 원문 확인). `pip install insightface` 하면 자동 다운로드되는
것이 여기 포함됩니다. 검출은 YuNet, 인식은 SFace(둘 다 OpenCV Zoo, Apache-2.0)로
대체했습니다. CodeFormer 도 S-Lab 1.0(non-commercial)이라 배제했습니다.

### 머리 최상부를 두 개 들고 있다
외교부 여권 규정의 머리 길이는 "정수리(**머리카락을 제외한** 머리 최상부)~턱 32~36mm"입니다.
- `crown` = 머리카락 최상부 → **프레임에 머리가 들어가는지** 판단
- `skull_top` = 두개골 최상부 → **규정상 머리 길이** 측정

실측에서 두 값이 2.5~3.5mm 차이 납니다. 하나로 합치면 머리숱 많은 사용자가 규격 미달로 반려됩니다.

### 전역 스무딩을 쓰지 않는다
잡티를 **개별로 healing** 한 뒤 주파수 분리를 약하게 겁니다. 전역으로 뭉개면 잡티와
함께 모공·솜털이 사라지고, **그 없어진 질감이 'AI 티'의 정체**입니다. 인핸즈 출력도
고주파가 오히려 증가(3.70→4.66)했습니다 — 매끄러운 피부를 요구하면 안 됩니다.

### 점을 지우지 않는다
여드름(어둡고 **붉다**)과 점(어둡고 **붉지 않다**)을 구분해 후자는 보존합니다.
점은 본인을 식별하는 특징입니다. 검증: 점 15/15 보존.

### 제거 면적에 상한이 있다
잡티 검출기는 완벽하지 않으므로 총 제거 면적을 **피부의 1.5%로 고정**하고 확신이 큰
후보부터 채웁니다. 기질이 나빠도 피해가 유계입니다. 정밀도가 0.25 → 0.53 으로 올랐습니다.

### 아이덴티티 예산을 자동으로 지킨다
`retouch.apply_within_budget()` 이 리터칭 후 Δcos 를 재고, 0.05 를 넘으면 전체 강도를
70% → 45% → 25% 로 물러섭니다. 리터처가 마지막에 "아직 이 사람으로 보이나" 확인하는
것과 같습니다.

### 피부톤 게이트는 밝기가 아니라 **색조** 기준
`sqrt(Δa*² + Δb*²) ≤ 9.0`. 밝기(L\*)로 걸면 정상 생성물이 전부 탈락합니다 —
인핸즈도 ΔL\* +29 입니다. **밝기는 조명이 정하고, 색조는 사람이 정합니다.**

### 라이선스는 차단이 아니라 스위치
`Config.licensing` 이 `"research"`(뭐든 씀)와 `"commercial"`(정리된 것만)을 가릅니다.
`license_audit()` 이 출시 전 구매·교체 목록을 자동으로 뽑습니다.

## 5. 잡은 버그 — 재발 방지

전부 **실제 사진으로 재봐서** 찾았습니다. 합성 테스트로는 하나도 못 찾았습니다.

| 버그 | 증상 | 원인 | 수정 |
|---|---|---|---|
| **YuNet 이 큰 이미지에서 붕괴** | 같은 사람 2장 유사도 **0.012** | 2576px 입력에서 검출 점수 0.63 → 랜드마크 부정확 → SFace alignCrop 오정렬 | 검출은 1280px 축소본, 좌표만 원본 스케일로 복원 → 유사도 **0.800** |
| 배경 샘플링이 옷을 읽음 | 매팅 전부 실패 | 증명사진은 어깨가 하단 모서리에 닿음 → 아래 모서리 = 정장. 일관성 116(허용 26) | 위쪽 모서리 + 어깨선 위 좌우 띠만 → 일관성 **0.0** |
| 피부톤 게이트가 L\* 기준 | 정상 생성물 전량 탈락 예정 | 인핸즈도 ΔL\* +29 | 색조(a\*,b\*) 기준으로 교체 |
| 선명도 정규화가 거꾸로 | 작은 얼굴일수록 값 폭증(521,787) | 크기로 나누지 않고 곱함 | ROI 를 256px 로 리사이즈 후 측정 |
| 선명도 지표 포화 | 과샤프닝을 못 잡음 | 상한 없는 단조 스코어 | 밴드 스코어(양쪽 벌점) |
| 그레인이 강도 0 에서도 적용 | "무보정"인데 노이즈 | 하한값을 잘못 둠 | 0 은 진짜 0, 해상도 비례 |
| white balance 가 얼굴색을 밀어버림 | 단독 Δcos **-0.082** | 유채색 배경을 조명 캐스트로 오인 | 배경 중성 확인 가드 + 이동량 상한 |
| `matte_uniform` NameError | 균일 매트 매번 예외 | 리팩터링 때 `h, w` 정의만 삭제 | 복원. 파이프라인 140초 → **1.5초** |

## 6. 이미 시도하고 버린 길 — 다시 하지 마세요

### 잡티 검출기 (3번 갈아엎음)

| 방식 | 재현율 | 정밀도 | 왜 버렸나 |
|---|---|---|---|
| p96 정규화 + 큰블러 잔차 | 0.00 | — | 정규화 분모를 얼굴 음영이 지배(dark p96=65 L단위) |
| DoG 밴드패스 + MAD z-score | 0.50 (한계) | 0.40 | 가우시안이 잡티 주변까지 흐려 대비 손실 |
| **black-hat/top-hat + MAD z-score + 면적 상한** | **0.42** | **0.53** | **채택** |

### 합성 픽스처가 무효였던 사건
고정 RGB 로 "여드름"을 칠했더니 절반이 주변 피부보다 **밝고 덜 붉게** 됐습니다
(ΔL +8, Δa −9). 검출기는 맞게 무시했는데 재현율 0 으로 보였습니다. `tests/synth.py` 는
**국소 피부값 대비**로 섭동을 줍니다 — 이 방식을 유지하세요.

### MediaPipe 종료 노이즈
atexit 으로 닫아봤더니 **더 나빠졌습니다**(마지막 참조가 사라져 `__del__` 이 두 번째로
닫으려다 실패). CLI 경계에서 unraisable 훅으로 mediapipe finalizer 예외만 거르는 방식이
정답입니다. 무관한 예외는 그대로 보고되는 것까지 확인했습니다.

### 키 위치를 코드로 추측
`geo_measure.py` 가 `geo_measure.env` 를 읽는 걸 보고 "Gemini 키가 거기 있다"고
단정했는데 **틀렸습니다**. 실제로는 `gemini.env` 에 있습니다. 반드시
`ai_keys.py status` 로 확인하세요.

## 7. 지켜야 할 규칙

### 키 (프로토콜 정본: `Yissue_Brain` 의 `Hermes/agents/_drafts/ai_api_key_access_protocol.md`)
- ⛔ 키 파일을 직접 읽지 않는다. `ai_keys.py` 한 곳으로만 받는다
- ⛔ `export KEY=$(grep ... .env | cut -d= -f2)` 금지 — 프로토콜 §3-3 의 금지 예시
- ⛔ 못 찾았을 때 **채팅으로 키를 요청하지 않는다**
- ⛔ 운영 키(`anthropic-prod`, `openai-winpub`) 사용 금지
- `--est-usd` 는 파일럿 실측값. 자동 구간은 작업당 $1 · 하루 $5
- ⛔ "진행해주세요"는 **비용 승인이 아니다.** 금액이 들어간 답만 승인

### 법
- **여권용으로 팔지 않는다.** 외교부가 배경 합성·편집 사진 제출을 명시 금지.
  `passport_kr` 은 미리보기 전용(`accepts_ai=False`)
- **AI 생성 표시**: 메타데이터만으로 부족. "AI 로 생성됨"을 **안내 문구로 1회 이상 별도
  제공**해야 함(AI기본법 2026-01-22 시행, 최대 3천만원 과태료). `docs/fact-check.md` §3
- 공공기관 채용은 AI 사진 불가 공고 확산 중 → 제출처별 가이드 필요

### 데이터
- 사용자 사진은 `samples/private/`(gitignore). 공개 저장소이고 얼굴은 민감정보
- 업로드 원본 7일 내 파기, 임베딩은 주문 종료 시 즉시 삭제

### 비용
- `gemini` 별칭은 **VPS GEO 주간 측정과 한도 공유**. 반복 튜닝이 잦아지면 키 분리
  (프로토콜 §7 미결 항목)
