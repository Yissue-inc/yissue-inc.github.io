## 1. MVP 범위 정의 — 무엇을 만들고, 무엇을 안 만드는가

MVP에서 가장 많이 실패하는 이유는 "다 만들려고 해서"입니다. 아래 표의 오른쪽 칸은 **의도적으로 버리는 것**입니다.

| 영역 | MVP에 넣는다 (IN) | MVP에서 뺀다 (OUT) |
|---|---|---|
| 피부 측정 | 정면 얼굴 1컷, 조명 통제 부스, 외부 API로 8~12개 지표 | 3D 스캔, 수분/유분 접촉식 센서, 두피·헤어 |
| 상담 | 터치 문진 4문항 + LLM 대화 2턴 (음성 출력, 터치 입력) | 자유 음성 대화, 다국어, 감정 인식 |
| 추천 | 20~40개 제품 카탈로그, 룰 기반 + 밴딧 | 전 브랜드 수천 SKU, 개인화 프로필 로그인 |
| 로봇 | **고정 슬롯 20구**에서 top-down 픽 → 배출 슈트로 전달 | 임의 위치 물체 픽킹, 사람 손에 직접 건네기, 얼굴에 발라주기 |
| 학습 | 전 세션 이벤트 로깅 + 오프라인 재학습 (주 1회 배치) | 온라인 실시간 학습, 강화학습, 모방학습(ACT/Diffusion Policy) |
| 운영 | 직원 1명 상주 전제, 원격 헬스체크 | 무인 24시간, 자동 재고 보충 |

> **"로봇이 사람 얼굴에 화장품을 발라주는 것"은 MVP에서 반드시 뺍니다.**
> 사람 얼굴에 접촉하는 로봇은 안전 등급·인증·보험 난이도가 10배 이상 올라가고, 사고 시 회복 불가능합니다.
> MVP는 **"집어서 건네주고, 발라보라고 안내한다"** 까지입니다. 이것만으로도 매장 임팩트는 충분합니다.

## 2. 사용자 여정 (목표 90초)

```
 [0s]  대기 화면 — 로봇이 천천히 idle 모션. 사람 감지(ToF/PIR)되면 인사 TTS
 [5s]  "피부 측정 해보실래요?" → 터치 [시작]
[10s]  개인정보·생체정보 동의 화면 (별도 동의 체크 2개) → 미동의 시 문진만으로 진행
[18s]  촬영 부스: 턱 받침 + 조명 3패턴(일반/편광/저각도) 자동 촬영 3컷
[21s]  분석 — 지표 8~12종 산출, 화면에 레이더 차트 + "가장 신경 쓰이는 3가지"
[30s]  문진 4문항 (피부타입 / 예산대 / 알러지 / 지금 쓰는 제품)
[45s]  LLM 상담 멘트 + 추천 2~3종 카드 노출 ("왜 이걸 추천했는지" 1줄 근거 필수)
[55s]  "실물로 보여드릴게요" → 로봇팔이 슬롯에서 제품 1을 집어 배출 슈트로 전달 (15s)
[70s]  제품 2 전달 (15s). 화면은 그동안 사용법 애니메이션 재생
[80s]  "손등에 발라보세요" 안내 + [발라봤어요 / 마음에 들어요 / 별로예요] 피드백 버튼
[90s]  (선택) 발림 부위 재촬영 → Before/After 비교 화면 ← 데모 임팩트 최고 구간
       QR로 상세 리포트 전송 (개인정보 최소 수집) / 구매는 직원 또는 POS 연동
```

**이벤트 로깅 포인트(별표는 학습 보상 신호):** 세션시작 · 동의여부 · 촬영성공 · 지표값 · 문진답변 · 추천리스트+순위 · 로봇전달성공 · **제품집어감\*** · **테스터사용\*** · **평점\*** · **구매\*** · 이탈지점

│  │       └ 손목 카메라(D405): 슬롯 empty 확인 + 파지 검증        │        │
│  └───────────────────────────────────────────────────────────┘        │
│                                                                        │
│  로컬 SQLite (오프라인 폴백) ──(야간 배치 동기화)──▶ 클라우드 Postgres    │
└────────────────────────────────────────────────────────────────────────┘
                                                          │
                                        ┌─────────────────┴────────────────┐
                                        │ 학습 파이프라인 (주 1회 배치)      │
                                        │ 로그 → 보상 산출 → 밴딧/모델 갱신  │
                                        │ → policy_version 태깅 → 배포      │
                                        └──────────────────────────────────┘
```

**설계 원칙 4가지**

1. **로봇은 "슬롯 번호"만 안다.** 인지·판단은 전부 상위 레이어. 로봇 드라이버는 `pick(slot_id) → deliver()` 두 함수뿐.
2. **모든 외부 의존(피부API·LLM·TTS)은 어댑터 인터페이스 뒤에 둔다.** 벤더 교체가 반나절 작업이 되도록.
3. **네트워크가 죽어도 세션은 끝까지 돈다.** 로컬 폴백: 룰 기반 추천 + 로컬 TTS + SQLite 로깅.
4. **정책 버전(`policy_version`)을 모든 추천 로그에 박는다.** 안 박으면 나중에 "뭐가 좋아졌는지" 절대 못 밝힙니다.

### 5.2 로봇팔 구현 — 초보자를 위한 4단계 사다리

로봇 픽앤플레이스는 **"물건이 어디 있는지 아느냐"** 에 따라 난이도가 10배씩 차이납니다.

| 레벨 | 방식 | 난이도 | MVP 적용 |
|---|---|---|---|
| **L1** | 드래그 티칭으로 포즈 저장 → 재생 (하드코딩 좌표) | ★☆☆☆☆ | ✅ **여기서 시작. MVP의 80%가 여기서 끝납니다** |
| **L2** | ArUco 마커로 지그 원점 보정 → 슬롯 좌표 오프셋 계산 | ★★☆☆☆ | ✅ 지그가 밀렸을 때 자동 복구 |
| L3 | MoveIt 2로 충돌회피 경로계획 + 임의 포즈 픽 | ★★★★☆ | ❌ MVP 제외 |
| L4 | 모방학습 (LeRobot / ACT / Diffusion Policy) | ★★★★★ | ❌ MVP 제외 (Phase 3 R&D) |

**L1 구현 절차 (실제로 이렇게 합니다):**

1. 제품 20종을 3D 프린팅 **슬롯 지그**에 세워 꽂는다. 슬롯마다 제품이 항상 같은 자세·같은 위치.
2. 로봇을 프리드라이브(드래그 티칭) 모드로 놓고, 슬롯 1의 파지 포즈로 손을 잡고 끌고 간다 → 좌표 저장.
3. 20번 반복 → `slots.json` 완성. (20분 걸립니다. 이게 "비전 픽킹"을 대체합니다.)
4. 궤적은 `approach(위 10cm) → descend → grip → lift → move_to_chute → release → home` 7단계 고정.
5. 100회 반복 테스트 → 실패 케이스만 좌표 미세조정.

> **이 트릭 하나가 프로젝트 3개월을 아낍니다.** "카메라로 아무 물건이나 집는 로봇"은 MVP가 아니라 박사논문입니다.

**파지 신뢰성 체크리스트**
- 그리퍼 핑거에 **실리콘/TPU 패드** 부착 (미끄럼 방지). 3D 프린팅으로 제품별 형상 맞춤 핑거 제작하면 성공률 급상승
- 그리퍼 **파지력을 제품별로 다르게** (튜브는 약하게, 유리병은 강하게) — `products.json`에 `grip_force` 필드
- 파지 검증: 그리퍼 개폐량 피드백 or 손목 카메라로 "잡혔는지" 확인 → 실패 시 1회 재시도 → 2회 실패 시 직원 호출
- 낙하 대비: 슈트 바닥에 폼 패드, 유리 제품은 MVP에서 제외(플라스틱·튜브만)

### 5.3 피부 측정 구현

**결론: 자체 모델을 만들지 마세요. API를 사세요.** 자체 모델은 라벨링된 한국인 피부 이미지 수만 장이 필요하고, 그건 이 프로젝트의 Phase 3입니다.

**촬영 파이프라인 (재현성이 전부):**
```
턱받침으로 거리 고정 (±5mm)
  → 암막 후드로 외광 차단
  → 조명 3패턴 자동 촬영
       ① 일반 확산광 : 전체 톤/홍조
       ② 교차 편광   : 표면 반사 제거 → 색소·기미·혈관
       ③ 평행 편광   : 표면 강조 → 결·모공·주름
  → 컬러체커로 화이트밸런스 보정 (매 촬영 프레임 모서리에 미니 체커 배치)
  → MediaPipe Face Mesh로 ROI 분할 (이마/양볼/코/턱)
  → API 전송 or 로컬 지표 산출
```

**MVP에서 로컬로도 계산 가능한 "정직한" 지표** (API 없이도 데모 가능):
| 지표 | 계산 방법 |
|---|---|
| 피부톤 (ITA°) | Lab 색공간 변환 후 ITA = atan((L*-50)/b*) × 180/π |
| 홍조 | a* 채널 평균 + 상위 분위 면적비 |
| 유분/광택 | 정반사 하이라이트 픽셀 비율 (일반광 − 교차편광 차분) |
| 결·거칠기 | 평행편광 영상의 고주파 에너지 (Laplacian variance) |
| 모공 | LoG 블롭 검출 개수/면적 |
| 좌우 균일도 | 좌/우 볼 ROI 간 통계 거리 |

> ⚠️ **표현 주의:** 화면·음성 어디에도 "진단", "치료", "질환"이라는 단어를 쓰면 안 됩니다.
> **"측정값", "상태", "관리 제안"** 으로 통일하세요. (10장 참고)

### 5.4 상담 대화 (LLM) 구현

- 입력: 피부 지표 JSON + 문진 답변 + 후보 제품 리스트(카탈로그 RAG)
- 출력 **구조화 강제**: `{ "greeting": str, "top_concerns": [str×3], "recommendations": [{product_id, reason_one_line}], "usage_tip": str }`
- 시스템 프롬프트에 **금지어 목록**(진단/치료/개선 보장/효능 단정)을 넣고, 출력 후 **금지어 필터**를 한 번 더 통과시킵니다. LLM만 믿지 마세요.
- 카탈로그에 없는 제품명을 지어내면 버리고 재시도(제품 ID 화이트리스트 검증).
- 지연: 스트리밍으로 첫 문장을 0.5초 안에 띄우고, 그 사이 로봇 픽 동작을 **병렬로 시작**합니다. 체감 속도가 완전히 달라집니다.

## 6. "똑똑해지는" 학습 루프 — 이 프로젝트의 진짜 심장

로봇팔은 데모용이고, **차별화는 데이터 플라이휠**에서 나옵니다. 그런데 초보 팀이 여기서 가장 많이 하는 실수는
"나중에 강화학습 붙이죠"라고 말하고 **로그를 안 남기는 것**입니다.

### 6.1 4단계 성장 경로

| 단계 | 필요 세션 수 | 방법 | 산출물 |
|---|---|---|---|
| **S0. 룰 기반** | 0 | 지표→제품속성 매핑 규칙표 (전문가/MD가 작성) | 콜드스타트 동작 + 학습용 prior |
| **S1. 컨텍스추얼 밴딧** | **~200** | LinUCB / 톰슨 샘플링. 팔(arm) = **제품 클러스터 10~30개** (개별 SKU 아님) | 추천 수락률 실측 개선 |
| **S2. 랭킹 모델** | ~2,000 | LightGBM 랭커 + 밴딧은 탐색 슬롯으로 유지 | 개인화 정교화 |
| **S3. 자체 피부 모델** | ~10,000 | 수집 이미지로 지표 모델 파인튜닝, 오프라인 정책평가(IPS/DR) | API 종속 탈피 + 독자 자산 |

> **왜 밴딧인가:** 매장 데이터는 "적고, 느리게 쌓이고, 탐색 비용이 실물 제품"입니다.
> 딥러닝은 데이터를 굶어 죽고, 밴딧은 200세션부터 실제로 작동합니다. **MVP에는 밴딧이 정답입니다.**

### 6.2 보상(reward) 설계

측정 불가능한 보상은 설계하지 마세요. MVP에서 **실제로 측정 가능한 것만** 씁니다.

```
r = 0.30 × 제품을_슈트에서_집어감      (카메라 or 로드셀로 확인 — 확실히 측정됨)
  + 0.30 × 테스터_사용함              (터치 버튼 "발라봤어요")
  + 0.20 × 명시적_평점 (1~5 → 0~1 정규화)
  + 1.00 × 구매                       (POS 연동 시. 없으면 직원 태블릿 입력)
  − 0.20 × 세션_중도_이탈
```
- 초기엔 **`집어감` + `평점` 2개만** 써도 충분합니다. 나머지는 파이프라인만 뚫어두고 가중치 0.
- 보상 산출은 **세션 종료 후 배치**로. 실시간 계산은 버그의 온상입니다.

### 6.3 반드시 피해야 할 3가지 편향 (초보자가 100% 밟는 지뢰)

| 편향 | 증상 | 대응 |
|---|---|---|
| **전달 순서 편향** | 로봇이 먼저 준 제품이 무조건 반응 좋음 → 모델이 "1번 슬롯이 최고"라고 학습 | 추천 순위와 **전달 순서를 랜덤화**하고, 순서를 피처로 로깅 |
| **노출 편향** | 추천된 적 없는 제품은 영원히 데이터가 없어 영원히 추천 안 됨 | ε=10% 탐색 슬롯 강제. top-3 중 1자리는 항상 탐색 |
| **직원 개입 편향** | 직원이 옆에서 "이게 좋아요" 하면 로봇 성과로 기록됨 | `staff_intervened` 플래그를 세션에 남기고 학습에서 제외 |

### 6.4 정책 배포 규율

- 모든 추천 로그에 `policy_version` 기록 (예: `rule-v1`, `linucb-v3`)
- 배포는 **주 1회**, 배포 전 **오프라인 재현 평가**(과거 로그로 새 정책 점수 추정 — IPS)
- 신정책은 **트래픽 20%** 로 1주 → 지표 확인 후 100%
- 롤백 스위치를 1개 커맨드로 (`POLICY=rule-v1 systemctl restart kiosk`)

session(id PK, started_at, ended_at, store_id, device_id,
        consent_personal BOOL, consent_biometric BOOL,
        staff_intervened BOOL, exit_stage TEXT, policy_version TEXT)

-- 측정 (원본 이미지는 기본 미저장. 동의 시에만 별도 암호화 보관)
skin_measurement(id PK, session_id FK, captured_at,
        metrics JSON,            -- {tone_ita, redness, oiliness, texture, pore, wrinkle, ...}
        capture_quality REAL,    -- 저품질이면 학습 제외
        image_ref TEXT NULL,     -- 동의 없으면 NULL
        analyzer TEXT, analyzer_version TEXT)

survey(session_id FK, age_band TEXT, skin_type TEXT, budget_band TEXT,
       concerns JSON, allergies JSON, current_products JSON)

-- 추천 (한 세션에 N행)
recommendation(id PK, session_id FK, product_id, rank INT, score REAL,
       is_exploration BOOL, policy_version TEXT, features JSON)

-- 로봇 동작
robot_action(id PK, session_id FK, product_id, slot_id, action TEXT,
       success BOOL, duration_ms INT, retry_count INT, error_code TEXT)

-- 피드백 (학습 보상의 원천)
feedback(id PK, session_id FK, recommendation_id FK NULL,
       kind TEXT,   -- picked_up | applied | rating | purchased | skipped
       value REAL, created_at)

-- 제품
product(id PK, brand, name, category, price, attrs JSON,  -- 성분/기능/타겟피부
        slot_id INT, grip_force INT, stock INT, active BOOL)
```

**철칙**
- 원본 얼굴 이미지는 **기본 저장 안 함**. 저장은 별도 동의 + 암호화 + 보관기간(예: 90일) + 자동 파기.
- 개인 식별자(이름·연락처)는 스키마에 아예 넣지 않습니다. 없으면 유출도 없습니다.
- 모든 테이블에 `created_at` 과 `schema_version`.

## 8. 안전 설계 — MVP의 1순위

### 8.1 물리적 안전 (설계로 해결, 소프트웨어로 해결하지 말 것)

| 위험 | 대책 |
|---|---|
| 로봇이 사람을 침 | **아크릴 인클로저로 완전 분리.** 사람 도달 가능 영역과 로봇 작업영역이 겹치지 않게 설계 |
| 손이 들어옴 | 인클로저 개구부는 **손이 안 들어가는 크기의 배출 슈트**만 (폭 12cm 이하, 각도 45°) |
| 정비 중 사고 | **도어 인터락 스위치** — 도어 열리면 안전 릴레이가 모터 전원 차단 |
| 폭주 | **E-Stop 버튼** 2개(전면/후면). 반드시 하드와이어드(소프트웨어 경유 금지) |
| 제품 낙하 | 슈트 폼 패드, 유리 제품 제외, 낙하 감지 시 세션 중단 + 직원 알림 |
| 정전 | UPS로 안전 정지 시퀀스 수행 후 셧다운 |
| 속도 | 매장 모드에서 TCP 속도 **250mm/s 이하**로 하드 리밋 (ISO/TS 15066 감속 기준 참고) |

### 8.2 소프트웨어 안전

- 워치독: 오케스트레이터가 3초 이상 응답 없으면 로봇 자동 홈 복귀 후 정지
- 동작 전 사전조건 검사: 도어 닫힘 · 슬롯 재고 있음 · 슈트 비어있음 · 이전 동작 완료
- 모든 로봇 명령에 타임아웃. 무한 대기 금지

## 9. 국내 법규·규제 체크리스트

> ⚠️ 아래는 **실무 체크리스트이지 법률 자문이 아닙니다.** 매장 파일럿 전에 반드시 개인정보 전문 변호사와
> 산업안전 전문가의 검토를 받으세요. 항목당 자문 비용은 수십~수백만원 수준이며, 예산에 반영해야 합니다.

### 9.1 개인정보보호법 (가장 중요)

- 얼굴 이미지에서 **특징정보를 추출·처리**하면 **생체인식정보 = 민감정보** 로 취급될 수 있습니다 → **별도 동의** 필요 (일반 개인정보 동의와 분리된 체크박스).
- 키오스크 UI 필수 요소: ① 수집 항목 ② 이용 목적 ③ 보유 기간 ④ 동의 거부 권리와 불이익 안내 ⑤ 별도 동의 항목 분리
- **설계로 리스크를 줄이는 법(권장):**
  - 원본 이미지를 **저장하지 않고** 지표(숫자)만 남긴다 → 민감정보 보관 리스크 대폭 축소
  - 분석을 **온디바이스**로 하면 외부 전송 동의 이슈가 사라짐 (API 사용 시엔 국외이전 동의 여부 확인)
  - 만 14세 미만 이용 제한 안내
- 개인정보 처리방침 게시, 파기 절차, 접근권한 관리, 유출 대응 절차 문서화

### 9.2 의료기기법 · 화장품법 (표현 규제)

- **금지:** "진단", "치료", "질환 판별", "여드름이 낫습니다", "주름이 없어집니다"
- **권장:** "피부 상태 측정", "미용 목적 정보 제공", "관리 제안"
- 기능성화장품이 아닌 제품에 기능성 표현 사용 금지. 광고 문구는 **화장품 표시·광고 실증제** 를 염두에 두고 작성
- 측정기기가 "의료기기"로 분류되지 않도록 **질병 진단 목적이 아님**을 UI·매뉴얼·마케팅 전반에서 일관되게 유지

### 9.3 로봇 안전

- 사업장 내 산업용 로봇은 산업안전보건법상 방호조치·안전인증 대상입니다. **매장(비산업 공간)에 설치되는 서비스 로봇의 적용 범위는 케이스별로 판단**이 필요하므로 반드시 확인하세요.
- MVP 전략: **인클로저로 완전 분리 + 협동로봇 안전기능 활성화** → "사람과 접촉 가능성 자체를 제거"하는 것이 인증·보험 부담을 가장 크게 줄이는 방법입니다.
- 위험성평가 문서 작성 (ISO 12100 프레임 참고), ISO/TS 15066 속도·힘 제한 값 문서화

### 9.4 그 외

- 전기용품 및 생활용품 안전관리법: 키오스크를 **제조·판매**하면 KC 인증 대상 검토
- 보험: **생산물배상책임보험 + 영업배상책임보험** 가입 (파일럿 전 필수)
- 매장 임대차·소방: 통로 폭, 비상구 확보
